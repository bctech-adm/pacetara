# Keputusan teknis

Catat setiap keputusan baru di bawah, dengan tanggal dan modul. Jangan ubah keputusan lama tanpa mencatat alasannya.

## Modul 1.1 Fondasi (10 Nov 2026)

1. **Akses database: `pg` + migrasi SQL mentah.** Tanpa ORM, karena PostGIS (geometry, fungsi spasial) lebih jelas ditulis dalam SQL. Migrasi berupa file `backend/migrations/NNNN_nama.sql`, dicatat di tabel `schema_migrations` beserta checksum, setiap file dijalankan dalam satu transaksi dengan advisory lock. Query builder (mis. Kysely) boleh ditambahkan di modul berikutnya bila perlu.
2. **Backend ESM + NestJS 12 + Vitest.** NestJS 12 hanya tersedia sebagai ESM, jadi backend memakai `"type": "module"` dan import berakhiran `.js`. Tes memakai Vitest dengan plugin SWC, karena esbuild tidak menghasilkan metadata dekorator yang dibutuhkan DI Nest. TypeScript dikunci di 5.9 karena TypeScript 7 (port native) belum didukung ekosistem tooling.
3. **API dan worker satu basis kode.** `backend/` menghasilkan satu image; service `api`, `worker`, dan `migrate` di Compose hanya beda perintah.
4. **Antrean: BullMQ di atas Redis.** Redis berjalan dengan `noeviction` agar job tidak hilang.
5. **Enkripsi kolom di aplikasi, bukan pgcrypto.** `FieldCrypto` memakai AES-256-GCM dengan format `v1 | iv(12) | tag(16) | ciphertext` dan AAD (mis. `users.email:<id>`) agar ciphertext tidak bisa dipindah antar baris. Byte versi memungkinkan rotasi kunci. Kunci tidak pernah masuk ke database atau query SQL.
6. **Blind index** untuk email dan nomor HP: HMAC-SHA256 dengan kunci terpisah (`BLIND_INDEX_KEY`) atas nilai yang dinormalisasi (email huruf kecil + trim, nomor HP format E.164 `+62…`). NIK memakai fungsi yang sama dengan konteks `nik` (HMAC berkunci, bukan hash biasa yang bisa di-brute force).
7. **Reverse proxy: Caddy.** HTTPS otomatis, TLS 1.2+ (TLS 1.1 ditolak, sudah diuji), HTTP diarahkan ke HTTPS, HSTS. Log akses tidak mencatat query string, `Authorization`, atau `Cookie`. Untuk lokal, domain `*.localhost` memakai CA internal Caddy. Port bisa diatur (`HTTP_PORT`, `HTTPS_PORT`) karena VPS dipakai bersama.
8. **Panel admin: Vite + React + TypeScript**, dibangun menjadi file statis dan disajikan container Caddy kecil dengan CSP ketat. URL API disuntikkan saat runtime (`config.js` dirender dari env `API_PUBLIC_URL`), jadi satu image bisa dipakai di semua lingkungan.
9. **wa-otp: layanan HTTP internal** dengan antarmuka `OtpProvider` (`BaileysProvider` sekarang, `CloudApiProvider` nanti, dipilih lewat `WA_PROVIDER`). API memanggil `POST /send` dengan header `X-Shared-Secret`. Selain 204, API (modul 1.2) wajib beralih ke OTP email. Login sesi lewat QR di log container atau kode pairing (`WA_PAIRING_NUMBER`). Nomor HP di log selalu disamarkan.
10. **Cadangan:** `pg_dump -Fc` → dienkripsi dengan `age` (public key di `.env`, private key tidak pernah di VPS) → diunggah dengan `rclone` ke remote di luar VPS. Data penyimpanan objek ikut dicadangkan sebagai tar terenkripsi. Diuji lokal: backup → hapus data → restore mengembalikan data dan PostGIS. Unggah ke remote belum diuji karena remote belum disiapkan.
11. **Certificate pinning ke CA, bukan ke leaf.** Dart `HttpClient` tidak memakai Network Security Config Android dan tidak memberi akses ke rantai sertifikat, jadi pin SPKI intermediate tidak praktis. Aplikasi memakai `SecurityContext(withTrustedRoots: false)` yang hanya mempercayai ISRG Root X1 dan X2 (berlaku sampai 2035 dan 2040). Caddy dikunci ke ACME Let's Encrypt (`acme_ca`) agar tidak beralih ke ZeroSSL. Mengganti CA berarti merilis aplikasi dengan root baru lebih dulu.
12. **Flutter:** Riverpod 3 (state), go_router (navigasi), dio (HTTP), flutter_secure_storage (Keystore). Base URL API lewat `--dart-define=API_BASE_URL`; build rilis menolak http dan alamat IP.
13. **Versi Node: 22 LTS** di image dan CI.
14. **Penyimpanan objek: SeaweedFS, bukan MinIO.** Per November 2026 image resmi MinIO (`minio/minio`, `minio/mc`, juga di quay.io) tidak lagi tersedia karena MinIO berhenti merilis build komunitas. Fork pihak ketiga tidak dipakai karena risiko rantai pasok. SeaweedFS (`chrislusf/seaweedfs`, Apache 2.0, image resmi pengelolanya) menyediakan API S3, jadi kode aplikasi memakai klien S3 biasa dan bisa pindah ke penyedia S3 lain hanya dengan mengubah `S3_ENDPOINT`. Versi image dikunci (`4.53`). Bucket privat dibuat oleh service `s3-init`.
15. **Healthcheck Postgres lewat TCP** (`pg_isready -h 127.0.0.1`). Saat inisialisasi pertama, server sementara hanya mendengarkan socket, sehingga healthcheck lewat socket lolos terlalu cepat dan migrasi gagal.
16. **Jaringan Docker:** `internal` (tanpa akses internet) untuk Postgres, Redis, S3; `edge` untuk layanan yang butuh keluar (API, worker, wa-otp, backup) atau menerima koneksi masuk (Caddy). Hanya Caddy yang mem-publish port. Container backend berjalan `read_only` dengan `no-new-privileges`.
17. **Catatan Windows (development):** jalankan Vitest dari path dengan huruf drive besar (`E:\...`). Jika shell memakai `e:\`, Vitest memuat dirinya dua kali dan gagal dengan "failed to find the runner". Tidak terjadi di CI (Linux).
