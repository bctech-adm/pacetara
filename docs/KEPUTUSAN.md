# Keputusan teknis

Catat setiap keputusan baru di bawah, dengan tanggal dan modul. Jangan ubah keputusan lama tanpa mencatat alasannya.

## Modul 1.1 Fondasi (10 Nov 2026)

1. **Akses database: `pg` + migrasi SQL mentah.** Tanpa ORM, karena PostGIS (geometry, fungsi spasial) lebih jelas ditulis dalam SQL. Migrasi berupa file `backend/migrations/NNNN_nama.sql`, dicatat di tabel `schema_migrations` beserta checksum, setiap file dijalankan dalam satu transaksi dengan advisory lock. Query builder (mis. Kysely) boleh ditambahkan di modul berikutnya bila perlu.
2. **Backend ESM + NestJS 12 + Vitest.** NestJS 12 hanya tersedia sebagai ESM, jadi backend memakai `"type": "module"` dan import berakhiran `.js`. Tes memakai Vitest dengan plugin SWC, karena esbuild tidak menghasilkan metadata dekorator yang dibutuhkan DI Nest. TypeScript dikunci di 5.9 karena TypeScript 7 (port native) belum didukung ekosistem tooling.
3. **API dan worker satu basis kode.** `backend/` menghasilkan satu image; service `api`, `worker`, dan `migrate` di Compose hanya beda perintah.
4. **Antrean: BullMQ di atas Redis.** Redis berjalan dengan `noeviction` agar job tidak hilang.
5. **Enkripsi kolom di aplikasi, bukan pgcrypto.** `FieldCrypto` memakai AES-256-GCM dengan format `v1 | iv(12) | tag(16) | ciphertext` dan AAD (mis. `users.email:<id>`) agar ciphertext tidak bisa dipindah antar baris. Byte versi memungkinkan rotasi kunci. Kunci tidak pernah masuk ke database atau query SQL.
6. **Blind index** untuk email dan nomor HP: HMAC-SHA256 dengan kunci terpisah (`BLIND_INDEX_KEY`) atas nilai yang dinormalisasi (email huruf kecil + trim, nomor HP format E.164 `+62…`). NIK memakai fungsi yang sama dengan konteks `nik` (HMAC berkunci, bukan hash biasa yang bisa di-brute force).
7. **Reverse proxy: Caddy.** HTTPS otomatis, TLS 1.2+ (TLS 1.1 ditolak, sudah diuji), HTTP diarahkan ke HTTPS, HSTS. Log akses tidak mencatat query string, `Authorization`, atau `Cookie`. Untuk lokal, domain `*.localhost` memakai CA internal Caddy. Port bisa diatur (`HTTP_PORT`, `HTTPS_PORT`) karena VPS dipakai bersama.
8. **Panel admin: Vite + React + TypeScript**, dibangun menjadi file statis dan disajikan container Caddy kecil dengan CSP ketat. URL API disuntikkan saat runtime (`config.js` dirender dari env `API_PUBLIC_URL`), jadi satu image bisa dipakai di semua lingkungan.
9. **wa-otp: layanan HTTP internal** dengan antarmuka `OtpProvider` (`BaileysProvider` sekarang, `CloudApiProvider` nanti, dipilih lewat `WA_PROVIDER`). API memanggil `POST /send` dengan header `X-Shared-Secret`. Selain 204, API (modul 1.2) wajib beralih ke OTP email. Login sesi lewat QR di log container atau kode pairing (`WA_PAIRING_NUMBER`). Nomor HP di log selalu disamarkan.
10. **Cadangan:** `pg_dump -Fc` → dienkripsi dengan `age` (public key di `.env`, private key tidak pernah di VPS) → diunggah dengan `rclone` ke remote di luar VPS. Data penyimpanan objek ikut dicadangkan sebagai tar terenkripsi. Diuji lokal: backup → hapus data → restore mengembalikan data dan PostGIS. Unggah ke remote belum diuji karena remote belum disiapkan.
11. **Certificate pinning ke CA, bukan ke leaf.** Dart `HttpClient` tidak memakai Network Security Config Android dan tidak memberi akses ke rantai sertifikat, jadi pin SPKI intermediate tidak praktis. Aplikasi memakai `SecurityContext(withTrustedRoots: false)` yang hanya mempercayai ISRG Root X1 dan X2 (berlaku sampai 2035 dan 2040). Caddy dikunci ke ACME Let's Encrypt (`acme_ca`) agar tidak beralih ke ZeroSSL. Mengganti CA berarti merilis aplikasi dengan root baru lebih dulu.
12. **Flutter:** Riverpod 3 (state), go_router (navigasi), dio (HTTP), flutter_secure_storage (Keystore). Base URL API lewat `--dart-define=API_BASE_URL`; build rilis menolak http dan alamat IP.
13. **Versi Node: 22 LTS** di image dan CI.
14. **Penyimpanan objek: SeaweedFS, bukan MinIO.** Per November 2026 image resmi MinIO (`minio/minio`, `minio/mc`, juga di quay.io) tidak lagi tersedia karena MinIO berhenti merilis build komunitas. Fork pihak ketiga tidak dipakai karena risiko rantai pasok. SeaweedFS (`chrislusf/seaweedfs`, Apache 2.0, image resmi pengelolanya) menyediakan API S3, jadi kode aplikasi memakai klien S3 biasa dan bisa pindah ke penyedia S3 lain hanya dengan mengubah `S3_ENDPOINT`. Versi image dikunci (`4.53`). Bucket privat dibuat oleh service `s3-init`.
15. **Healthcheck Postgres lewat TCP** (`pg_isready -h 127.0.0.1`). Saat inisialisasi pertama, server sementara hanya mendengarkan socket, sehingga healthcheck lewat socket lolos terlalu cepat dan migrasi gagal.
16. **Jaringan Docker:** `internal` (tanpa akses internet) untuk Postgres, Redis, S3; `edge` untuk layanan yang butuh keluar (API, worker, wa-otp, backup) atau menerima koneksi masuk (Caddy). Hanya Caddy yang mem-publish port. Container backend berjalan `read_only` dengan `no-new-privileges`.
17. **Catatan Windows (development):** jalankan Vitest dari path dengan huruf drive besar (`E:\...`). Jika shell memakai `e:\`, Vitest memuat dirinya dua kali dan gagal dengan "failed to find the runner". Tidak terjadi di CI (Linux).

## Deploy pertama (10 Nov 2026)

18. **VPS bersama memakai Traefik yang sudah ada, bukan Caddy.** Port 80/443 di VPS Hostinger dipegang Traefik (file provider saja, CrowdSec, resolver `le-http`). PaceTara dijalankan dengan `docker-compose.vps.yml` yang menonaktifkan Caddy dan menyambungkan `pacetara-api` serta `pacetara-admin` ke network `web-edge`. Rute ada di `infra/traefik/pacetara.yml`, dipasang ke `/opt/infra/traefik/dynamic/clients/pacetara.yml` lalu `docker exec traefik kill -HUP 1`. Stack ada di `/opt/infra/web/clients/pacetara`. Di VPS khusus nanti, cukup `docker-compose.yml` saja (Caddy aktif lagi).
19. **Pin juga root Let's Encrypt generasi Y (Root YE, Root YR).** Sertifikat produksi diterbitkan intermediate YE2 → Root YE, yang saat ini di-cross-sign oleh ISRG X2 → X1. Rantai diverifikasi lolos baik terhadap X1/X2 maupun Root YE saja, jadi aplikasi tetap tersambung setelah cross-sign dicabut.
20. **Image sementara dikirim manual** (`docker save` → `scp` → `docker load`, tag = commit) karena repo belum punya remote GitHub. Setelah remote dan GHCR siap, ganti `REGISTRY`/`IMAGE_TAG` di `.env` VPS dan pakai `docker compose pull`.
21. **Kunci cadangan:** public key age ada di `.env` VPS; private key di laptop pemilik (`%USERPROFILE%\pacetara-backup-age.key`). Pindahkan ke pengelola kata sandi; tanpa kunci itu cadangan tidak bisa dipulihkan.

## Modul 1.2 Akun dan login (10 Nov 2026)

22. **Token:** akses = JWT HS256 15 menit berisi `sid` (id family sesi); penyegar = 32 byte acak, hanya SHA-256-nya disimpan, dirotasi setiap dipakai, umur 30 hari. Memakai token penyegar yang sudah dirotasi = indikasi pencurian → seluruh family dicabut. Family yang dicabut dicatat di Redis selama umur token akses, sehingga logout/hapus akun/reset kata sandi langsung menolak token akses yang masih berlaku. Aplikasi wajib me-refresh satu per satu (single-flight), karena dua refresh paralel akan dianggap pemakaian ulang.
23. **Guard global:** semua endpoint wajib token akses kecuali yang ditandai `@Public()` (health, config, register, login, google, refresh, lupa/atur ulang kata sandi). Endpoint baru otomatis terlindungi.
24. **Kata sandi:** Argon2id via `@node-rs/argon2` (prebuilt, tanpa install script), parameter OWASP m=19 MiB, t=2, p=1. Login dengan email tak terdaftar tetap menjalankan verifikasi hash palsu agar waktu respons sama. Pesan galat sama untuk email salah dan kata sandi salah.
25. **Kode verifikasi:** 6 digit, disimpan sebagai HMAC berkunci (kunci diturunkan dari `BLIND_INDEX_KEY`), target (email/HP) disimpan terenkripsi. Sekali pakai, 5 kali salah lalu hangus, jeda kirim ulang 60 detik, maksimal 5 kode/jam per tujuan. Berlaku 10 menit (email) atau 5 menit (WhatsApp).
26. **OTP nomor HP:** WhatsApp lebih dulu; setiap respons wa-otp selain 204 (atau timeout 8 detik) → kode baru dikirim ke **email akun yang sudah terverifikasi**. Jika email belum terverifikasi, cadangan ditolak (503 `otp_unavailable`) agar kode tidak dikirim ke alamat yang belum dibuktikan. Karena itu urutan di aplikasi: verifikasi email dulu, baru nomor HP.
27. **Level 1 dihitung database** (trigger `users_compute_level`): email dan HP terverifikasi = 1. Level 2 tidak diturunkan oleh trigger.
28. **Login Google:** ID token diverifikasi di server (`google-auth-library`, `aud` ∈ `GOOGLE_CLIENT_IDS`). Akun baru wajib persetujuan privasi (428 `privacy_required`). Menautkan Google ke akun email yang sudah ada hanya jika Google menyatakan `email_verified`, untuk mencegah pengambilalihan akun.
29. **Kebijakan privasi berversi** (`PRIVACY_POLICY_VERSION`). Pendaftaran wajib mengirim versi yang sama dengan server; jika naskah diperbarui, versi lama ditolak (428 `privacy_outdated`).
30. **Hapus akun = anonimisasi**, bukan DELETE baris: semua data pribadi di-NULL-kan, nama menjadi "Pengguna dihapus", token dan kode dihapus, foto dihapus dari penyimpanan. Constraint `users_deleted_is_anonymous` memaksa tidak ada data pribadi tersisa pada akun berstatus `deleted`. Email dan nomor HP bisa dipakai lagi untuk akun baru. Modul berikutnya wajib menambah langkahnya sendiri di `UsersService.deleteAccount` (chat pribadi, lari, dsb.).
31. **Foto profil:** jenis dicek dari isi berkas (sharp), maks 8 MB dan 50 MP, di-encode ulang ke WebP 512 px sehingga seluruh EXIF/GPS terbuang. Tidak ada URL S3 publik: aplikasi mengambil `/v1/users/:id/avatar` dengan token, lewat Dio yang ber-pinning (bukan `Image.network`, yang tidak memakai pinning).
32. **Email:** SMTP via nodemailer, STARTTLS wajib di produksi. Lokal memakai Mailpit (`docker compose --profile dev up`, UI di http://127.0.0.1:8025).
33. **Tes e2e** (`backend/test/*.e2e.spec.ts`) memakai Postgres+PostGIS dan Redis sungguhan (`TEST_DATABASE_URL`, `TEST_REDIS_URL`), dengan email/WhatsApp/Google/S3 dipalsukan. Tanpa variabel itu suite dilewati. CI menjalankannya di job "Migrasi + tes e2e".
34. **gitleaks di CI** dijalankan sebagai CLI atas seluruh riwayat, karena gitleaks-action gagal pada push pertama ke repo kosong (tidak memindai apa pun tetapi tetap merah).

## Pengerasan image (10 Nov 2026)

35. **Gerbang Trivy di CI** (HIGH/CRITICAL yang sudah ada perbaikannya) memblokir push image. Pemindaian pertama menemukan: npm bawaan `node:22-alpine` (10 HIGH, bukan dependensi aplikasi), `gosu` di image server `postgres` (26, termasuk 1 CRITICAL), dan `golang.org/x/net` di Caddy v2.11.9 (1 HIGH, belum diperbaiki di rilis Caddy mana pun). Perbaikannya:
    - Runtime Node (backend, wa-otp): `apk upgrade` + npm, npx, corepack dihapus. Perintah container memanggil `node` langsung, jadi npm tidak dibutuhkan.
    - Backup: `alpine:3.24` + `postgresql16-client` (pg_dump/pg_restore 16.15), bukan image server postgres. Backup → restore diuji ulang.
    - Panel admin: Caddy diganti nginx dari `alpine:3.24`, berjalan sebagai user `nginx` (non-root). `config.js` dan CSP ditulis `admin/entrypoint.sh` dari `API_PUBLIC_URL` (divalidasi ketat: hanya `https://domain[:port]`). Menggantikan keputusan #8 (directive templates Caddy).
    - Semua image akhir menjalankan `apk upgrade` agar patch Alpine terbaru ikut walau base image tertinggal.
36. **Action pihak ketiga di CI dikunci ke commit SHA** (mulai dari trivy-action v0.36.0), karena tag bisa dipindah ke kode lain.
